# HTML & CSS – Grading Rubric

This document explains how your work is evaluated.

## Grading Status

Each module will receive one of the following statuses:

 **Status** | **Meaning**                                                                 

**Complete**  | All required files are present and all checklist items are satisfied.  
 
**Needs Correction**  | Files exist but important requirements are missing or incorrect.

**Incomplete**  | Major files are missing or the work does not meet the basic standard.

There are no percentage scores at this stage.  
The goal is mastery of the fundamentals.

## What We Evaluate

### 1. Requirements (Highest Priority)
- All required files are present
- Filenames are exactly as specified
- Every item in the module `CHECKLIST.md` is correctly done

### 2. HTML Quality
- Valid HTML5 boilerplate (`<!DOCTYPE html>`, `lang`, charset, viewport)
- Correct use of semantic elements when required
- Logical heading hierarchy
- Clean and readable indentation

### 3. Accessibility Basics
- Proper heading order
- Meaningful `alt` text on images (when images are required)
- Form controls correctly associated with labels (when forms are required)
- Descriptive link text (no “click here”)

### 4. Completeness of Content
- Content is sufficient to demonstrate the concept
- Not empty tags or extremely minimal placeholders (unless the task is purely structural)

## What Does **Not** Affect Your Grade

- The exact text or topic you choose (as long as it is appropriate)
- Visual design / CSS (in pure HTML modules)
- Perfect English or spelling
- Extra features beyond the requirements

## Resubmission Policy

If your work is marked **Needs Correction** or **Incomplete**:

1. Fix the issues.
2. Push the updated files to the same GitHub repository.
3. Notify your reviewer that you have resubmitted.

You may resubmit until the work meets the required standard.

## Academic Integrity

You are encouraged to discuss concepts with classmates.  
However, the code you submit must be your own work.  
Copying another student’s files is not allowed.
